# Auto-Update Issue Fix

## Problem

The GitHub Actions workflow was failing to publish release assets with a **403 Forbidden** error:

```
HttpError: 403 Forbidden
"Resource not accessible by integration"
```

## Root Cause

The default `GITHUB_TOKEN` in GitHub Actions has **read-only** permissions by default. It needs **write** permissions to upload release assets and create releases.

## Solution Applied

### 1. Updated GitHub Workflow Permissions

**File:** `.github/workflows/release.yml`

Added explicit permissions at the workflow level:

```yaml
permissions:
  contents: write
  packages: write
```

This grants the workflow the necessary permissions to:

- Create and modify releases
- Upload release assets
- Write to the repository contents

## Next Steps

### Option 1: Push the Changes (Recommended)

1. Commit and push the updated workflow file:

   ```bash
   git add .github/workflows/release.yml
   git commit -m "fix: add write permissions for GitHub Actions auto-updates"
   git push origin main
   ```

2. Create and push a new version tag:

   ```bash
   git tag v1.0.5
   git push origin v1.0.5
   ```

3. The GitHub Actions workflow will automatically:
   - Build the application for all platforms
   - Package the installers
   - Create a GitHub release
   - Upload the installers as release assets
   - Publish `latest.yml` for auto-updates

### Option 2: Alternative - Use Personal Access Token (PAT)

If the above doesn't work, you may need to use a Personal Access Token:

1. Go to GitHub Settings → Developer Settings → Personal Access Tokens → Tokens (classic)
2. Generate new token with these scopes:
   - `repo` (full control)
   - `write:packages`
3. Add it to your repository secrets as `GH_TOKEN`
4. Update the workflow to use `${{ secrets.GH_TOKEN }}` instead of `${{ secrets.GITHUB_TOKEN }}`

## How Auto-Updates Work

### Configuration

- **Update Server:** GitHub Releases
- **Update Check:** Automatically checks on app startup (production mode)
- **Manual Check:** Available in Help → Check for Updates menu

### Files Required for Auto-Updates

1. **Installer:** `POS System Setup 1.0.x.exe`
2. **Update Manifest:** `latest.yml` (auto-generated by electron-builder)
3. **Blockmap:** `*.blockmap` (for differential updates)

### Update Process

1. App checks GitHub Releases for `latest.yml`
2. Compares current version with latest version
3. Downloads update in background if available
4. Notifies user when download completes
5. Installs update on user confirmation

## Common Issues

### Issue: "Update not available" message

**Cause:** Version in `package.json` is not higher than installed version
**Fix:** Increment version number before building

### Issue: Update downloads but doesn't install

**Cause:** App doesn't have write permissions to installation directory
**Fix:** Ensure NSIS installer includes `allowElevation: true`

### Issue: 403 error during publish

**Cause:** Insufficient GitHub token permissions
**Fix:** Applied in this commit (added `permissions` to workflow)
